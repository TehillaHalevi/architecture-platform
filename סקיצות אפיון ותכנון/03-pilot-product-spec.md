

# 03 — אפיון המוצר ותנאי קבלה | אפיון הפיילוט

**מעמד:** החלטות הפיילוט שסוכמו בשיחה. **סביבת שימוש:** דפדפן במחשב נייח או נייד בשני הצדדים.

> **✓ סוכם** — דרישת פיילוט. **◇ להמשך** — נושא לאפיון הראשי. **? פתוח** — החלטה שעדיין נדרשת.

## 3.1 | מסכים וניווט

| מסך | התנהגות בפיילוט |
|---|---|
| טופס פנייה ציבורי | שליחה בלי התחברות. סימון שדות שגויים ושמירת יתר הטופס. אישור קבלה לאחר שמירה. |
| לוח האדריכלית | פניות חדשות ומטופלות, כניסה קבועה לפרויקטים, „מחכה לך” לתיקונים, „ממתין ללקוח” לאישורים, והאישור האחרון עם הפרויקט, הסקיצה, החלופה אם צוינה, הגרסה, התאריך וקישור ישיר. |
| רשימת פרויקטים | שם ושלב מרכזי בכל שורה. חיפוש לפי שם הפרויקט או שם הלקוח, כולל חלק מהשם ולפני הצטרפות. תוצאה ריקה מציגה „לא נמצאו פרויקטים”. ניקוי מחזיר את הרשימה. |
| כרטיס פרויקט של האדריכלית | פתיחה ועריכה, פרטי קשר, מצב הזמנה וקישור לסקיצות. הזמנה נשלחת בפעולה מפורשת. המצבים כוללים טרם נשלחה, ממתינה, התקבלה, פגה, בוטלה או הוחלפה. כשל שליחה מציע ניסיון חוזר. |
| כניסת לקוח והזמנה | חשבון שגוי מציע החלפת חשבון ושומר את הפרטים מוסתרים. אחרי התחברות מקישור חוזרים ליעד. קישור שפג או בוטל מציע פנייה באתר. קישור שהתקבל פותח את הפרויקט אם הגישה תקפה. |
| אזור אישי | פרויקט אחד נפתח ישירות. כמה פרויקטים מוצגים ברשימה עם מצב וסימון פעולה. „כל הפרויקטים” זמין מתוך פרויקט רק כשיש יותר מאחד זמין. כשאין גישה, מוצגים הסבר ופעולת פנייה, ובחשבון לא משויך גם החלפת חשבון. |
| סקירת הפרויקט | שם ושלב מרכזי, „מחכה לך”, ואז „מה חדש” מצומצם. פריטים פתוחים מוצגים לפי מועד יעד, איחורים ראשונים ומועדים עתידיים מהקרוב לרחוק, ואז פעולות בלי יעד. לכל פריט שם, יעד אם נקבע וקישור. ההנחיה המלאה בתוך הבקשה. במצב ריק מוצג שאין פעולות. |
| סקיצות | שורה לכל סקיצה. שם מוביל לגרסה העדכנית, וקישור נפרד לגרסה האחרונה שאושרה אם היא שונה. אפשר לפתוח „גרסאות קודמות” עם תאריכי פרסום ושרשורים לפי הרשאות. הלשונית גלויה גם לפני הפרסום הראשון. „מה חדש” מפנה לפרסום האחרון שעדיין זמין, עם התאריך המקורי, גם אם אינו הגרסה העדכנית. |
| עמוד בקשת אישור | במחשב מוצג PDF לצד החלופה, הגרסה, ההנחיה, היעד והפעולות „אישור הגרסה” ו„בקשת תיקון”. שדה התיקון נפתח באותו עמוד. ליד סקיצה עם בקשה פתוחה האדריכלית מקבלת קישור לבקשה הקיימת. |
| עמוד בקשת תיקון | האדריכלית רואה את המקור והטקסט ויכולה להעלות גרסה חדשה ישירות. הלקוח רואה בעמוד הסקיצה ובקישור המקורי „בטיפול האדריכלית” או „טופלה בגרסה…” וקישור לגרסה המתוקנת. |
| משוב לפעולה | אחרי שליחה או אישור מוצלח מופיע חלון קטן עם × ו„חזרה לפרויקט”. הסגירה משאירה באותו עמוד. סטטוס, תאריך וזהות המאשר זמינים לפי הרשאות. תקלה זמנית מציעה ניסיון חוזר. |

**◇ להמשך:** תפריט ציבורי עם „אזור אישי”, תיק עבודות עם שיוך השראה לפנייה, תצוגה בנייד, סינון פרויקטים לפי מצב, עד שני שלבים נוספים בסקירה לפי סדר ומעבר לכל השלבים אם יש יותר, הדמיה ראשית מפורסמת שנבחרת במפורש, שורת הנחיה בכרטיס פעולה, היסטוריית עדכונים וסימון נקרא, השוואה בין גרסאות, התקדמות, מסמכי פרויקט, פגישות ויומן, צ׳אט צף ותיק פרויקט סופי. מיקום הודעת השהיה פתוח.

## 3.2 | מבנה המידע

| רשומה | נתונים וקשרים |
|---|---|
| פרויקט ופנייה | מזהים נפרדים. לפרויקט בעלות ופרטי קשר משלו. שם פרויקט אינו ייחודי. מזהה פעולת יצירה נאכף בנפרד ומאפשר ניסיון חוזר בטוח. |
| חשבון, שיוך והזמנה | חשבון לאדם. שיוך מקשר חשבון לפרויקט והרשאות. הזמנה נפרדת מקשרת פרויקט, מייל, הרשאה מתוכננת, מצב ופקיעה. קבלה יוצרת שיוך. הזמנות קודמות נשמרות בהיסטוריה. |
| שלב | פרויקט, שם, סדר, מצב, יעד אופציונלי. הפרויקט מחזיק הפניה לשלב המרכזי. |
| סקיצה וגרסה | סקיצה שייכת לפרויקט. לכל גרסה PDF, מספר, מצב ותאריך פרסום אם פורסמה. לסקיצה הפניה מפורשת לגרסה העדכנית. גרסה שפורסמה שומרת את הקובץ שמקושר לה. |
| בקשת אישור | גרסה, חלופה אם נדרשת, נמען, יעד והנחיה אופציונליים. מצבים: פתוחה, אושרה, נענתה בבקשת תיקון, נסגרה. בסגירה נשמרת הסיבה, למשל ביטול, גרסה חדשה, הסרת גרסה או הסרת גישה. איחור נגזר מהיעד כשהבקשה פתוחה. |
| אישור ובקשת תיקון | אישור נפרד עם הבקשה, המאשר והמועד. בקשת תיקון נפרדת עם מקור, תוכן, מחבר, זמן, מצב וגרסת תיקון בעת סגירה. |
| שרשור ותשובה | שרשור שייך לגרסה, עם מצב וקישור אפשרי לגרסת תיקון. כל תשובה שומרת מחבר וזמן. |
| מצב מייל | תוצאת ניסיון השליחה האחרון ומועדו נשמרים בנפרד ממצב הבקשה. ניסיון חוזר משתמש באותו כרטיס או בקשה, בהתאם למסלול. |

רשימות ההמתנה נגזרות מהבקשות הפתוחות ומהצד שאמור לפעול. פרסום גרסה, סגירת בקשה, אישור והסרת גישה חייבים להישאר עקביים גם כשפעולות מגיעות במקביל. בפיילוט „מה חדש” נגזר מגרסאות שפורסמו וזמינות.

**◇ להמשך:** אירועי עדכון נפרדים, היסטוריית שליחות, כמה מאשרים, קישור סקיצה לשלבים, סוגי שלב וחשיפה פנימית או ללקוח.

## 3.3 | הרשאות וחשיפה

- האדריכלית מנהלת את הפרויקטים שלה ואת ההזמנות, הטיוטות, הפרסומים, הבקשות והאישורים.
- לקוח שהצטרף יכול לעיין בגרסאות שפורסמו וזמינות לו, לפתוח הערה על הגרסה העדכנית ולהשיב בשרשור ישן. המאשר יכול לאשר או לבקש תיקון רק בבקשה פתוחה שהוקצתה לו.
- הרשאות נבדקות גם בפתיחת קישור ישיר לקובץ ובכל ניסיון לבצע פעולה. הסרת גישה חוסמת קריאה וכתיבה לפרויקט, מציגה דרך חזרה לאזור האישי וסוגרת בקשות אישור פתוחות של המשתמש. גישה לפרויקטים אחרים נשמרת.
- **◇ להמשך:** הרשאות צפייה בלבד, תגובה, אישור וניהול פגישות לפי משתתף. משתתף מורשה לצפות יכול לראות „ממתין לאישור”. חשיפת שם המאשר לשותפים עדיין פתוחה. כניסה בקוד חד־פעמי למייל תצטרף ל־Google, עם תוקף עשר דקות, שימוש אחד, ביטול קוד קודם בשליחה חדשה והגבלת ניסיונות.

## 3.4 | התראות וחיבורים

| אירוע בפיילוט | נמען וערוץ |
|---|---|
| פנייה על פרויקט חדש | אישור באתר לפונה ומייל לאדריכלית עם קישור לכרטיס. |
| הזמנה או שליחה מחדש | מייל לכתובת שהוזמנה. רק ההזמנה האחרונה תקפה, לשבעה ימים. |
| בקשת אישור חדשה | מייל אחד למאשר עם קישור ישיר, לצד פעולה באתר. |
| תזכורת לבקשה פתוחה | מייל ידני לבחירת האדריכלית עם הקישור הקיים. |
| תיקון או אישור מהלקוח | עדכון בפרויקט ובלוח האדריכלית. תיקון נכנס ל„מחכה לך”. |
| פנייה על גישה או קישור שפג | טופס באתר שמגיע ללוח האדריכלית. |

**◇ להמשך:** מייל אישור לפונה על פרויקט חדש, מענה והצעות, מסירה ועדכון מסירה, פקיעת גישה, פתיחה או הארכת גישה, הפסקה וחידוש שמחייב פעולה. השלמה נכללת במייל המסירה. השהיה מוצגת באתר. ביטול פגישה שולח מייל למוזמנים בפועל. תשלומים ושחרור תוצרים יפורטו באפיון התשלומים. תזכורת אוטומטית תישלח פעם אחת לבקשה פתוחה שהאדריכלית הפעילה, 24 שעות לפני היעד, בכפוף לחלון השליחה שסוכם. חיבור ליומן חיצוני נשמר להמשך.

## 3.5 | תנאי קבלה לפיילוט

| בדיקה | תוצאה נדרשת |
|---|---|
| פנייה תקינה, לא תקינה, כפולה, כשל מייל וסיום טיפול | אישור לאחר שמירה תקינה, תצוגת שגיאות בלי אובדן הטופס, כרטיס והתראה אוטומטית אחת לכל פעולה, ניסיון חוזר על אותו כרטיס, ושימור הכרטיס כ„טופלה”. |
| שמירה והזמנה | שמירה יוצרת פרויקט ללא שליחה. לחיצה כפולה או ניסיון חוזר יוצרים אחד בלבד. פרויקט חדש יזום יכול לשאת אותם פרטים. |
| הזמנה תקפה, חשבון שגוי, פקיעה והחלפה | רק החשבון שהוזמן יכול להצטרף לאחר קבלה מפורשת. קישור שפג, בוטל או הוחלף מוביל להסבר ולפנייה. כשל במייל משאיר את הפרויקט ומאפשר שליחה חוזרת, עם לכל היותר קישור תקף אחד. |
| ניווט וסקיצות ריקות | ניתוב לפי מספר הפרויקטים וההרשאות. לשונית סקיצות גלויה גם לפני פרסום. החיפוש עובד לפי שם מלא או חלקי ומחזיר רשימה מלאה בניקוי. |
| טיוטה, פרסום, כשל והסרה | ניתן להחליף טיוטה. רק פרסום מוצלח מעדכן גרסה וסוגר בקשה ישנה. קובץ שהוסר חסום ישירות, עם העדר גרסה עד בחירה או פרסום. |
| הערות | שרשור נפתח בגרסה עדכנית בלבד. גרסה קודמת מאפשרת תשובה לשרשור קיים. עדכון בזמן כתיבה שומר טיוטה. טיפול שומר קישור לגרסת התיקון, והאדריכלית מחליטה אם לפתוח מחדש. |
| סבב מלא | בקשת אישור לגרסה וחלופה מסוימות מופיעה בשני הלוחות. תיקון מייצר רשומה נפרדת ועובר לאדריכלית. לאחר פרסום וסגירה מפורשת הלקוח רואה קישור לתיקון. אישור לבקשה חדשה נשאר על הגרסה שאושרה. |
| קדימות בין אישור לפרסום | אישור שנשמר ראשון משויך לגרסה המקורית. אם הפרסום נשמר ראשון, הבקשה נסגרת והמערכת מפנה לגרסה העדכנית. |
| הרשאות | שני לקוחות ושני פרויקטים לדוגמה. קישור לפרויקט אחר וקישור ישיר לטיוטה או לגרסה שהוסרה חסומים. הסרת גישה בעת צפייה חוסמת אישור, סוגרת בקשה פתוחה ומשאירה פרויקט אחר זמין. |
| מייל אישור ותזכורת | קישור שורד התחברות ומוביל לבקשה. כשל מייל משאיר את הבקשה בלוח ומאפשר שליחה חוזרת. תזכורת ידנית לבקשה פתוחה מציגה יעד מעודכן. בקשה סגורה חוסמת תזכורת, ותיקון נשאר באתר. |

בדיקת שימושיות מקצה לקצה תתבצע בדפדפן במחשב משני הצדדים. הלקוח משלים תיקון ואישור ללא הדרכה. האדריכלית מזהה מיד מה עדכני, מה אושר ולמי מחכים. הבדיקות יבוצעו לאחר הפיתוח.

## מעבר לשלב 4

**✓ מסד נתונים:** SQL Server. **העדפת שרת:** C#. **המלצה לבחינה:** ASP.NET Core Web API עם Entity Framework Core. **? פתוח:** אישור המסגרת וממשק ה־Frontend, בחירת אחסון PDF פרטי ושירות מייל. סדר הפיתוח שהוצע הוא השלמת רצף הסקיצות מקצה לקצה ולאחריו מסלול הפנייה הציבורית.
